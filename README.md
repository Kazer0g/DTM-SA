# DTM-SA: Distributed Text Mining & Sentiment Analysis

DTM-SA trains a sentiment model and runs a distributed (Spark-based) inference + text-mining pipeline with validation, scalability tests, and dashboard generation.

---

## What Runs What

- `model/train_model.py`  
  Trains and selects the best sentiment model candidate, then saves model artifacts and train/test CSV files.

- `src/run_pipeline.py`  
  Runs only the core MapReduce-style pipeline (prediction + top terms + runtime stats).

- `src/scalability.py`  
  Runs multiple pipeline executions with different `max_docs` and `chunk_size`.

- `src/validate.py`  
  Compares pipeline predictions with ground-truth labels and writes metrics.

- `src/visualize_results.py`  
  Builds a single dashboard image from scalability, validation, prediction, and term-report outputs.

- `src/runner.py`  
  Orchestrates everything end-to-end in this order:
  1) pipeline  
  2) scalability (optional)  
  3) validation  
  4) visualization (optional)

## Model Training

### Data Sources

- `SetFit/sst5` (movies)
- `Yelp/yelp_review_full` (restaurants)
- `cardiffnlp/tweet_eval` sentiment split (tweets)

### Training Workflow

`model/train_model.py` does:

1. Load source datasets.
2. Map labels to 3 classes: `negative`, `neutral`, `positive`.
3. Sample per dataset (`SAMPLE_SIZE`, currently large for stronger accuracy).
4. Build `model_input` as `"<category> <text>"`.
5. Split into train/test (80/20, stratified).
6. Train multiple TF-IDF + linear candidates.
7. Select best candidate by validation accuracy (with macro-F1 tie-break).
8. Refit best model on full training split.
9. Evaluate on held-out test split.
10. Save:
    - vectorizer/classifier artifacts
    - metadata JSON
    - generated `data/train.csv` and `data/test.csv`

### Current Accuracy Target

The updated training path is configured to reach around 70% accuracy in project evaluation.

## Pipeline (MapReduce-style) Overview

`src/pipeline.py` is the core engine.

### Map phase (distributed inference)

- Reads CSV with robust parsing (`header`, `multiLine`, `quote`, `escape`).
- Uses Spark RDD `mapPartitions` to:
  - load artifacts once per partition
  - batch texts
  - emit predicted sentiment per row

### Reduce phase (term aggregation)

- Tokenizes text with cleaning for stop words and escaped-sequence artifacts (`\n`, `\uXXXX`, etc.).
- Aggregates term counts by sentiment.
- Produces top-N overall terms for each sentiment.
- Adds up to 5 example messages for each top term.

### Main pipeline outputs

- `results/predictions.csv`
- `results/group_term_sentiment_report.json`
- `results/work_statistics.json`
- `results/pipeline_runtime.json`

## Validation, Scalability, Visualization

### `src/validate.py`

- Computes classification metrics and confusion matrix.
- Includes robust alignment logic for prediction-vs-label comparison.
- Saves `validation_results.json`.

### `src/scalability.py`

- Runs repeated pipeline benchmarks across:
  - document counts
  - chunk sizes
- Saves summary CSV and per-run artifacts.

### `src/visualize_results.py`

- Generates `dashboard.png` with runtime/quality/term charts.

## Usage

### Train model artifacts

```bash
cd model
python train_model.py
```

### Run full workflow (recommended)

```bash
cd src
python runner.py --input-csv ../data/test.csv --output-dir ../results
```

### Run pipeline only

```bash
cd src
python run_pipeline.py --input-csv ../data/test.csv --output-dir ../results
```

### Run validation only

```bash
cd src
python validate.py \
  --input-csv ../data/test.csv \
  --predictions-csv ../results/predictions.csv \
  --output-json ../results/validation_results.json
```

### Run visualization only

```bash
cd src
python visualize_results.py \
  --scalability-csv ../results/scalability_results.csv \
  --validation-json ../results/validation_results.json \
  --group-report-json ../results/group_term_sentiment_report.json \
  --predictions-csv ../results/predictions.csv \
  --output-png ../results/dashboard.png
```

### Run scalability only

```bash
cd src
python scalability.py \
  --input-csv ../data/test.csv \
  --output-csv ../results/scalability_results.csv \
  --output-dir ../results/scalability_runs \
  --doc-counts "100,500,1000" \
  --chunk-sizes "500,1000,2000"
```

## Notes

- If input has no `group` column, pipeline uses `unknown`.
- Run training first if model artifacts are missing in `model/models/`.
- `runner.py` accepts `--skip-scalability` and `--skip-visualization` for faster smoke runs.
